## 기타 이상과 미검증

엄격 harness의 전체 `ok:false` 및 실패 exit는 그대로 보존한다. 차단된 백그라운드 요청3건은 `AUTH_SETTINGS_READ_NOT_ALLOWED`, `FIXED_PUBLIC_SOURCE_RPC_tn_public_membership_product_catalog`, `OTHER_ORIGIN_OR_METHOD`다. 마지막 항목의 실제 origin/원인은 아직 미분류다. fatal route0·page error0·business writes allowed0이며 이3건을 무해하다고 단정하지 않는다. 이전에도 존재한 제한과 새 수신 흐름 성공을 구분한다.

추가 증거1회: 독립 QA가 로그인 없는 격리 DEV 페이지에서 GET `https://appleid.cdn-apple.com` 차단을 관측했고, 기존 소스의 Apple 로그인 버튼 이미지 참조를 확인했다. 이전 미분류 요청의 유력한 후보이지만 그 요청 자체의 직접 origin 기록은 없으므로 동일성을 확정하지 않는다. 실제 로그인·수업 전달은 재실행하지 않았다. 이 남은 항목은 `VERIFY ONLY`이며 전체 harness 실패를 성공으로 재기록하지 않는다. 새 수신 기능의 실제 흐름에서 로그인·핵심 이동 실패나 저장 요청은 관측되지 않았다.

이 결과는 정상 비밀번호 API+실제 호스팅 화면+기존 관리자 탭의 수신 증거다. 소셜 로그인 UI, PIN 이후 재개, 실제 iPhone Safari 또는 새 네이티브 빌드의 완료 증거는 아니다. 업데이트 안내의 소스/합성 검수와 실제 정식 업데이트 노출도 구분한다. 현재 운영 웹·네이티브 빌드·내부 업로드는 아직 V16 미반영이다.
