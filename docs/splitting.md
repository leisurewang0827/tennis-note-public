# 큰 파일 쪼개기

세 앱의 `app.js` 를 이 방법으로 53,312줄 → 1,648줄로 줄였고 **이 방법으로는
사고가 한 건도 없었습니다.**

## 절차

1. 함수 본문을 **한 글자도 바꾸지 않고** 새 파일로 옮깁니다.
2. **되돌리기 검증**: 뗀 것을 제자리에 도로 넣으면 원본과 바이트 단위로 같은가.
   같으면 내용이 안 바뀌었다는 증명입니다.
3. `git show HEAD:...app.js` 와 대조해 **개수 · 본문 · 유실 · 중복** 을 확인합니다.
4. 새 파일을 [등록할 곳](structure.md#새-파일을-만들면-등록할-곳) 에 등록합니다.
5. `./scripts/verify.sh`
6. **브라우저로 봅니다.** 정리하다 낸 사고 4건이 전부 여기서만 드러났습니다.

함수의 끝은 **열 0 의 `}`** 로 찾습니다. "다음 `function` 선언 전까지" 로 잡으면
사이의 최상위 코드까지 함수로 오인합니다 (실제로 사고를 냈습니다).

왜 이게 안전한지는 [docs/structure.md](structure.md#왜-호출부를-안-바꾸고-옮길-수-있나).

## 어느 폴더로 보낼지 — 이름이 아니라 동작으로 가르세요

이름 규칙(`sync*`, `render*`)으로 가르면 관리자에서 60개가 잘못 들어갑니다.

```
서버(Supabase)를 부르는가            → data/
localStorage 를 만지는가              → storage.js
HTML 문자열을 만드는가                → views/
DOM 을 만지고 이름이 open/close/toggle → ui/
DOM 을 만지는가                       → forms/
아무것도 안 하는가                    → domain/
```

폴더별 정의는 [docs/structure.md](structure.md#폴더가-뜻하는-것).

**`bindEvents` 와 `initApp` 은 옮기지 마세요.** 부팅 진입점입니다.
`bindEvents` 는 호출 목록뿐이라 "순수" 로 분류돼 `domain/` 으로 간 적이 있습니다
(`event-binding` 검사가 잡았습니다).

## 최상위 선언(`const`)은 함수와 다릅니다

로드 시점에 평가되므로 **순수 리터럴만** 옮기세요. 남겨야 하는 것:

- `performance.now()` 처럼 시점에 의존하는 것
- `window.TennisNoteXxx` 를 읽는 것
- 함수를 부르는 것
- **그런 것을 참조하는 것** — 전이적으로 제외해야 합니다

⚠ **전개 구문 `...name` 을 참조로 세세요.** 정규식으로 앞 문자가 점이면 제외하도록
짜면 `...name` 을 놓칩니다. 실제로 이 때문에 다른 파일의 값을 쓰는 상수를 먼저
실리는 파일에 넣어 로드 시점에 터뜨렸습니다.

⚠ 서로 참조하는 상수를 **다른 파일로 갈라놓지 마세요.** 참조가 양방향이면 파일
순서로 풀 수 없습니다. 얽힌 것은 원본 순서가 보존되는 한 파일에 모으세요.

## `bindEvents` 는 특별히 다룹니다

한 함수를 자르는 것이라 바이트 대조가 그대로는 안 됩니다. 대신 **조각을 원래
줄 순서로 도로 이으면 원본 본문과 같은가** 를 확인합니다.

`document`·`window` 리스너는 서로 순서가 얽히므로 **`delegated.js` 에 원래 순서
그대로** 모읍니다. 나머지는 서로 다른 요소라 순서가 결과를 바꾸지 않습니다.

`stopImmediatePropagation` 을 쓰면 이 전제가 무너집니다 — `event-binding` 검사가 막습니다.

캡처 단계 리스너(`addEventListener(..., true)`)는 버블 리스너보다 항상 먼저
실행되므로 등록 순서와 무관합니다. 옮겨도 됩니다.

## 기본값 이음매는 쓰지 마세요

전역을 매개변수로 바꾸되 기본값을 그 전역으로 두는 방식입니다.

```js
function f(candidate)                        // 이전
function f(candidate, allLessons = lessons)  // 이후
```

**102개 함수에 적용하고 멈췄습니다.** 시그니처가 바뀌어 바이트 대조를 할 수 없고,
그래서 **두 번 사고가 났습니다.** 위의 "함수 통째로 옮기기" 로 충분합니다.

이미 적용된 것들이 남아 있어 검사 셋이 계속 지킵니다. **기존 이음매를 만질 때만**
아래를 지키세요.

⚠ 배열 메서드에 콜백으로 그대로 넘겨지던 함수는 깨집니다. `map`/`flatMap`/`filter`
는 콜백에 `(요소, 인덱스, 배열)` 을 넘기므로, 매개변수를 추가하는 순간 **인덱스가
이음매 자리에 들어갑니다.**

```js
branchMembers.flatMap(memberCoachNames)              // 깨진다
branchMembers.flatMap((m) => memberCoachNames(m))    // 이렇게 감싸야 한다
```

- **매개변수 이름은 `all` 로 시작합니다.** `undefined-identifiers` 검사가 이 접두사를
  기준으로 검사합니다. 다른 이름을 쓰면 그 검사가 비켜갑니다.
- `seam-callback` 이 콜백 문제를, `seam-scope` 가 이름이 함수 밖으로 새는 것을 봅니다.
